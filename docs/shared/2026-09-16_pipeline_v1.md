# Pipeline — judge labeling and block-boundary resampling — reasoning-trace-experiments — 2026-09-16 v1

File: 2026-09-16_pipeline_v1.md (local version 1 = chat version 5 of the chat begun 2026-09-15). Claude drafts, Kian confirms. Status: confirmed by Kian on 2026-09-16; nothing in it has been implemented yet — it is the specification the scripts are written to. Changes to it are new versions (Option A), never edits in place. Companion documents: 2026-09-14_labeling_scheme_v3.md (rules, notation 0d, block-level quantities 0e; v4 pending), 2026-09-14_action_summary_v4.md (design, motivation, cost; v5 pending), 2026-09-15_source_traces_labeled_v2.md (the reviewed labels).

## 0. Purpose

1. Turn the reviewed labeling of the two source traces into a reproducible machine pipeline: split, judge, resample at block boundaries, judge the continuations, analyze.
2. Produce the two quantities of the design, each read against two baselines below the first block — the no-think baseline P(answer = a | no thinking), the model's answer with no reasoning tokens at all, and P(answer = a | cut-0), thinking from an empty prefix —: P(answer = a_T | cut(B_m)) for every resampled block (the mediation tree) and P(next = Y | cut(B_m)) for every resampled block (the transition tree), plus the two references of the anti-Markov comparison: P_corpus(Y | X), the count-based node-to-node transition matrix of the 44 sweep traces (no position, no resampling), and P_source(next | cut), the label of the node that actually follows each cut in the source trace (one-hot, the trace's own path), both as defined in labeling scheme Section 0d.
3. Scope of the first run: one item (bat-and-ball with "$1.00 more" deleted), one model (Qwen 3.6-27B via DeepInfra raw completions), the two source traces c004 (C-trace) and e036 (E-trace), budget about $100.

## 1. Decisions taken (2026-09-15, Kian)

1. Machine files are JSONL, one JSON record per line. Reason: sentences contain newlines, quotes, commas, dollar signs and pipes, which JSON escapes losslessly; records need nesting (two labels on a combined sentence, a usage dict per call); a line-oriented file survives a crash and can be resumed; the existing sweep and resample runs are already JSONL.
2. CSV is used only for small summary tables meant to be read or opened in a spreadsheet; each CSV table has a Markdown twin in the run's summary.
3. One file per collection, never one file per trace; every record carries `trace_id`. Collections: `source` (c004, e036), `sweep44` (the 44 traces of condition eval0_multi0), `archived500` (the 500 archived continuations), and each new resampling run.
4. The judge (LJ) receives one call per trace with the full trace, all sentences numbered, and returns a label for every sentence in one strict-JSON reply. Reason: labels depend on context ("Yes." is labelable only next to its question).
5. The judge labels all three levels. Level 3 may be ignored in the analysis if it proves uninformative; it costs nothing to collect.
6. The judge prompt is generated from labeling scheme v4, with every example quoted from c004 or e036 paraphrased or removed, so that the judge has not seen the answers it is tested on; the agreement numbers on the source traces still carry the caveat that the rules were written on those traces.
7. Cut positions for the resampling run come from the reviewed blocks (2026-09-15_source_traces_labeled_v2.md), not from the judge's blocks. The judge's agreement on the source traces measures how far its labels can be trusted on continuations, where no human review exists.
8. Prefixes are raw trace text from character 0 to the end of the block's last sentence, never re-joined sentences.
9. Cuts run strictly sequentially, block by block, so the stopping rule (labeling scheme 0e) can stop a trace before the next cut is paid for; continuations within one cut run in parallel.
10. Unresolved continuations ("?") stay in the denominator of P̂, which is always n; the "?" count is reported per cut.
11. n per cut: candidate 40; fixed in the pre-registration, step (6/9). The budget now allows n = 80 at the stopping-rule scale (Section 8), a precision gain from a standard error of 0.079 to 0.056 at P = 0.5; Kian chooses n in (6/9).
12. Judge: Claude Haiku 4.5 via the API, pinned model id `claude-haiku-4-5-20251001`, temperature 0 (Kian, 2026-09-15, on cost). Sonnet 5 (`claude-sonnet-5`) is the fallback if Haiku's agreement in step (4e/9) is judged too low; GPT-5.6 Luna ($0.20/$1.20) is cheaper still but unproven on a three-level scheme, and GPT-5.4/5.5 ($2.50/$15 and $5/$30) are not cheaper than the Claude options.
13. Judge output is compact: one line per run of consecutive sentences sharing a label, with label codes, never the document text and never full label paths (Kian, 2026-09-15). The script expands runs to sentences; blocks are derived, never returned by the judge, because a block is a sequence of nodes with different labels and opens where an opener sentence sits. Detail in step (3c/9).
14. Batch mode for every judge collection that is not needed immediately — sweep44, archived500, the new continuations (steps 5 and 8) — at half price; ordinary calls for the two source traces in step (4/9). Batch and non-batch use the same model and give the same output at temperature 0; the only difference is delivery: a batch is submitted as one job of up to 100,000 requests, processed asynchronously (most finish within an hour, all within 24 hours or the remainder expires unbilled), results downloadable for 29 days. A reply cannot steer the next request inside a batch, which matters only for the DeepInfra sampling, where the stopping rule runs cut by cut and which is not a Claude call.
15. Budget for the whole pipeline: up to $160 (Kian, 2026-09-15). The design at n = 40 needs about $28 (Section 8).
16. No-think baseline (Kian, 2026-09-16): the pipeline samples the model's answer with thinking disabled — an empty thinking block prefilled, `<think>\n\n</think>\n\n`, after which the model answers at once — with the same item prompt, template and scorer as every other cut, n_0 = 100 samples. It is the System-1 answer distribution for this item, the reference below cut-0 (which is thinking on, empty prefix: P(E) = 0.80, P(C) = 0.12, 4,450 reasoning tokens on average in the archived run), and it was never measured in the frozen study. Reported descriptively next to P(a | cut-0) and P_m; it is not part of the Δ_m sequence (Δ_0 stays defined against cut-0). The empty-block form is the Qwen 3 chat template's `enable_thinking=False` convention and is verified against the Qwen 3.6 model card before use (Section 5, item 8).

4a. `runs/tests/` — one folder per test run, `runs/tests/t<k>_<step>_<date>_<hhmm>/`, holding the test's artifacts and a `TEST_REPORT.md` (Section 9); Kian reads the report before the next step is allowed to run. Test folders are committed; they are the evidence that each mechanism worked before money was spent.
4b. `scripts/tests/` — unit tests (`pytest`) for the pure functions: splitter, code parser, derivation, stopping rule, P̂ and interval arithmetic; free, run before every API step.
5. `figures/` — plots written by `s4_analyze.py`.
6. `docs/shared/` — this document, the scheme, the summary, the listings; `docs/claude/` — STATE files.

## 3. Files and records

1. Raw traces (read only): `archive/decided-mid-thought/runs/sweep_items_batball_2026-08-19_1623.jsonl` — field `trace` is the thinking text, `usage.completion_tokens_details.reasoning_tokens` its exact token count; the source traces are `condition == "eval0_multi0"` with `sample == 2` (c004) and `sample == 40` (e036); the 44 traces of that condition form `sweep44`.
2. Raw continuations (read only): `archive/decided-mid-thought/runs/resample_cuts_2026-08-25_1503.jsonl` — 500 records, field `cont_text`; ids like `rs0823_cut015_003` (`prefix_id` `rs0823_cut015`, `trace_arm` c004 or e036, `cut` in the run's numbering, `seq` 0–24).
3. `sentences_<collection>.jsonl` — one record per sentence: `trace_id`, `s` (0-based), `char_start`, `char_end` (end exclusive, offsets into the raw text), `text`; for the source traces also `old_s` and `part` (1 for a sentence identical to an old one, 2 or 3 for the later parts of an old sentence split by the equation rule); for continuations `s` counts from 0 within the continuation and the record carries `cut_block`.
   Example: `{"trace_id": "c004", "s": 17, "old_s": 16, "part": 1, "char_start": 741, "char_end": 761, "text": "\n        *   Does Bat > Ball?"}`
4. `labels_source_reviewed.jsonl` — Kian's reviewed labels, exported once from the confirmed listing: `trace_id`, `s`, `labels` (a list of one or two `{"L1", "L2", "L3"}` objects, `L2` or `L3` null where the path stops), `combined`, `source` = "reviewed_v2".
   Example: `{"trace_id": "c004", "s": 17, "labels": [{"L1": "Reasoning", "L2": "calculation", "L3": "algebra"}], "combined": false, "source": "reviewed_v2"}`
5. `labels_<collection>_judge.jsonl` — the judge's labels, same shape as item 4 plus `raw_reply`, `model`, `prompt_version`, `temperature`, `run_id`, `timestamp`, `usage`, `attempt` (1 or 2), `valid` (true when the reply passed validation).
6. `blocks_<collection>_<source>.jsonl` — one record per trace, derived from a label file by the derivation code (Section 4, step 4d): `trace_id`, `label_source`, `nodes` (list of `{"name", "L1", "s_start", "s_end", "n"}`), `blocks` (list of `{"m", "s_start", "s_end", "opener_rule": "R1"|"R2"|"R3", "opener_label", "tokens"}`); `tokens` is null until a token count exists (Section 4, step 7f).
7. `continuations_<run_id>.jsonl` — one record per sampled continuation, the archived record format plus `block` (the m of cut(B_m)), `prefix_char_end`, `prompt` (the exact string sent), `model`, `temperature`, `max_tokens`, `seq`, `cont_text`, `finish`, `think_closed`, `letters`, `chosen`, `usage`, `timestamp`.
8. `pcut_<run_id>.csv` — one row per sampled condition: `trace_id` (`shared` for the two baselines), `m` (`nothink`, `cut0`, then 0, 1, 2, …), `n`, `count_C`, `count_E`, `count_other`, `count_unresolved`, `p_hat` (of a_T for trace cuts; both P̂(C) and P̂(E) are recoverable from the counts), `ci_low`, `ci_high`, `prompt_tokens`, `tk_block`, `mean_completion_tokens`, `cost_usd`, `stopped` (true on the cut where the stopping rule fired).
9. `agreement_<collection>.csv` — one row per label and level: `level`, `label`, `n_reviewed`, `n_judge`, `agreement`, `kappa`, `jaccard`; plus `residue_<collection>.csv` with every disagreement: `trace_id`, `s`, `reviewed`, `judge`, `text`.
10. `pcorpus_L1.csv` — the corpus transition matrix at Level 1: rows the current node label X, columns the next node label Y, cells the counts of consecutive node pairs across the 44 sweep traces, plus a row-normalized copy (P_corpus(Y | X)). `psource_<trace>.csv` — one row per cut of the source trace: `m`, `last_node_label` (the Level 1 label of the node that ends the block), `source_next_label` (the label of the node that actually follows in the source; at a block-end cut this is an opener label by construction), i.e. P_source as a one-hot reference row. `pnext_<run_id>.csv` — one row per resampled cut: `m`, `last_node_label`, `n`, and one column per Level 1 label with the count of continuations whose first new node carries that label (P̂(next = Y | cut(B_m)) after dividing by n), plus a column `opens_block` for continuations whose first new node is an opener.
11. `config.json` in every run folder — endpoint, model string, template, temperature, max_tokens, n, workers, prompt version, input file hashes, git commit of `scripts/` at run time.
12. `_log.txt` in every run folder — one line per cell: attempted, succeeded, failed, retried, cost so far.
13. The Markdown listing Kian reviews (`[date]_source_traces_labeled_v*.md`) is a generated view of items 3, 4 and 6; it is never a data source.

## 4. The algorithm

(1/9) Fix the inputs.
(1a/9) Raw text is read only from the two archived JSONL files of Section 3, items 1 and 2.
(1b/9) Export `labels_source_reviewed.jsonl` from 2026-09-15_source_traces_labeled_v2.md; gate: 375 + 254 records, every label path in the scheme's inventory.
(1c/9) Nothing in `archive/` is edited; every derived file is written under `runs/experiments/<run_id>/`.

(2/9) `s0_split.py` — the splitter.
(2a/9) Implement the equation-rule splitter of labeling scheme Section 1 in code.
(2b/9) Gate: on c004 and e036 the output matches the confirmed listing sentence for sentence — 375 and 254 sentences with identical boundaries; on failure the splitter is fixed, never the listing.
(2c/9) Write `sentences_source.jsonl`, `sentences_sweep44.jsonl`, `sentences_archived500.jsonl`.
(2d/9) The same function is called by `s3_judge_continuations.py` for every new continuation.

(3/9) `s1a_make_prompt.py` — the judge prompt.
(3a/9) Generate `prompts/judge_prompt_v1.md` from labeling scheme v4: Level 1 definitions, the full Level 2 and Level 3 inventory with one-line glosses, the combined-sentence rule (at most two labels), the self-question rule, the opener rules for information only, and the output format.
(3b/9) Paraphrase or remove every example quoted from c004 or e036 (decision 6).
(3c/9) Output format demanded of the judge: plain text, one line per run of consecutive sentences with the same label, `<first>-<last> <code>` (a single sentence as `<first> <code>`), a combined sentence on its own line with two codes joined by `+`, no prose. Example: `15-22 Re.ca.al` for sentences 15 to 22 labeled Reasoning > calculation > algebra; `67 Re.hw.ev+Rf.me.b` for a combined sentence. About 4 output tokens per sentence instead of 15 for full paths in JSON.
(3c'/9) Codes: generated deterministically from the inventory — two letters for Level 1 (Pl, Re, Rf, Kn, Rs, As, Ex, Co), two or three letters for each Level 2 and Level 3 leaf, listed with their full names in the prompt and in `labels_v1.json`; a path stops where the scheme stops.
(3c''/9) Validation of a reply: every line parses; the runs cover 0 … N−1 exactly once, in order, without gaps or overlaps; every code exists in `labels_v1.json`; at most two codes per sentence. The script expands runs to one record per sentence (Section 3, item 5).
(3d/9) Write `prompts/labels_v1.json`: the list of allowed paths at each level with their codes, used for validation and decoding.
(3e/9) Both files are pinned; the prompt version and the model string are written into every judge record.

(4/9) `s1_judge.py` on the source traces (master plan step 3/5).
(4a/9) One ordinary (non-batch) call per trace: the prompt, then all sentences of the trace numbered `s0 … s374`; Haiku 4.5, pinned model id, temperature 0.
(4b/9) Validate the reply as in (3c''/9); one retry on failure, then the trace is logged as failed and the run stops for inspection.
(4c/9) Write `labels_source_judge.jsonl` (Section 3, item 5).
(4d/9) Run the derivation — Planning runs, openers R1/R2/R3 at the start of a run, blocks, nodes, names — on the judge's labels; write `blocks_source_judge.jsonl`. The same code, run on `labels_source_reviewed.jsonl`, must reproduce the confirmed listing's 46/37 blocks and 193/146 nodes exactly; this is the derivation gate.
(4e/9) Compare judge with reviewed labels: `agreement_source.csv` (kappa and Jaccard per label at Levels 1, 2 and 3) and `residue_source.csv`; report with the caveat of decision 6.
(4f/9) Cost: two calls of roughly 15k input tokens each; cents. Gate: Kian reads `agreement_source.csv` and `residue_source.csv` and decides whether Haiku stays the judge or (4/9) is rerun with Sonnet 5 (decision 12).

(5/9) `s1_judge.py` on the other collections — the zero-cost pilot (master plan step 4/5).
(5a/9) `sweep44`, as one batch: labels, nodes and blocks per trace; from the node sequences, `pcorpus_L1.csv`, the corpus transition matrix at Level 1 (counts of consecutive node labels across the 44 traces, about 1,700 pairs).
(5b/9) From the reviewed nodes of c004 and e036, `psource_c004.csv` and `psource_e036.csv`: for every cut, the label of the last node before it and the label of the node that follows it in the source (the reference row for that cut).
(5c/9) `archived500`, as one batch: each archived continuation is judged as in step (8/9), with its archived prefix shown labeled; from the blocks, `pnext_archived.csv`, the first new block type after each archived cut — the first empirical P(next = Y | cut) at zero DeepInfra cost.
(5d/9) These runs are the end-to-end test of steps (2/9) to (4/9) and (8/9) before any money is spent on sampling.
(5e/9) Judge cost for the 546 documents with Haiku 4.5, codes and batch: about $6 (Section 8).

(6/9) Pre-registration of stage one (master plan step 5/5, first half).
(6a/9) Written from the reviewed blocks: the ordered list of sampled conditions — the no-think baseline (n_0 = 100), cut-0 (n), then cut(B_0), cut(B_1), … for each trace (the cut of the last block is the whole trace and is not resampled).
(6b/9) n per cut (candidate 40), temperature 1.0, max_tokens 16000, the scorer, the "?" convention.
(6c/9) The stopping rule stated as an assumption: stop a trace at the first cut where all n continuations end in a_T; later blocks trivial by assumption.
(6d/9) The descriptive report: P(a | no thinking) and P(a | cut-0) as the two baselines; P_m and Δ_m with 95% intervals, the top block, Tk(B_top) against Tk(trace), the gap with its interval, the plots; no thresholds.
(6e/9) The transition comparison: P(next = Y | cut(B_m)) at Level 1 against P_corpus and P_source; the null of no type dependence; the sequence test.
(6f/9) Cost ceiling $100; stage two excluded and to be registered separately if taken.
(6g/9) Committed and pushed before step (7/9) runs.

(7/9) `s2_resample.py` — the run.
(7a'/9) Baselines first, once, shared by both traces: the no-think condition — template with the item prompt and the prefill `<think>\n\n</think>\n\n`, n_0 = 100 samples, scored like every other continuation (a reply that opens a new `<think>` despite the closed block is logged and scored on whatever letter it resolves to, and counted in `_log.txt`); then cut-0, n samples with the empty prefix `<think>\n`. Both rows go into `pcut` as `nothink` and `cut0`; cost under $1 and about $0.60 respectively.
(7a/9) For each source trace, for m = 0, 1, 2, …: prefix = raw trace text `[0, char_end of the last sentence of B_m)`; prompt = the archived template with the item prompt and the prefix (Section 5); the exact prompt string is stored in every record.
(7b/9) n continuations per cut, `workers` in parallel within the cut; cuts strictly sequential.
(7c/9) Score each final reply with the archived scorer (`extract_letters`, verbatim); "?" when no letter is resolved; denominator always n.
(7d/9) Compute P̂_m and its Wilson 95% interval; if `count_aT == n`, record M = m, mark `stopped`, and end that trace.
(7e/9) Write `continuations_<run_id>.jsonl` and `pcut_<run_id>.csv`; append to `_log.txt` after every cut.
(7f/9) Tk(B_m) = `usage.prompt_tokens` of cut(B_m) minus `usage.prompt_tokens` of cut(B_{m−1}) — the model's own token count of the block, from the API, no tokenizer download needed; Tk(B_0) against cut-0; written into `pcut`. The no-think row has no Tk.
(7g/9) Cost guard: the script stops when the cumulative cost passes the registered ceiling; resumable with `--resume`.

(8/9) `s3_judge_continuations.py`.
(8a/9) Split each new continuation with `s0` (sentences `c0, c1, …`).
(8b/9) One judge request per continuation, submitted as one batch per resampling run: the prefix with the reviewed labels shown, then the continuation's numbered sentences; the judge labels only the continuation.
(8c/9) Validate as in (3c''/9); failed requests are re-submitted once in a follow-up batch; write `labels_continuations_<run_id>.jsonl`.
(8d/9) Derivation on prefix plus continuation; write `blocks_continuations_<run_id>.jsonl`, which gives the first new node and block after the cut and the continuation's whole block sequence.

(9/9) `s4_analyze.py` — numbers and figures, no API.
(9a/9) From `pcut`: the two baselines P̂(a | no thinking) and P̂(a | cut-0) for every answer letter, with intervals; then per trace P_m, Δ_m with intervals, the top block B_top, Tk(B_top) and Tk(trace), the gap Δ_(1) − Δ_(2) with its interval, the plots of P_m and Δ_m against m with the two baselines drawn as reference lines.
(9b/9) From the continuation nodes: P̂(next = Y | cut(B_m)) at Level 1 per cut (`pnext`); the pooled forms P̂(next = Y | X) over cuts ending in an X node and P̂(next = Y | W --> X) over cuts with a W node earlier, and the order comparison P(next = Y | W --> X) against P(next = Y | X --> W); the observational-versus-resampled test, each cut's `pnext` row against the row of `pcorpus_L1.csv` for its `last_node_label`; each cut's row against its `psource` reference (how often the continuations do what the source did, and how often they open a new block at all); the sequence test.
(9c/9) Outputs: CSV tables, a Markdown summary in the run folder, figures in `figures/`.
(9d/9) Only then the stage-two decision from the plot (node-level cuts inside B_top, or both top blocks under the near-tie rule), registered separately if taken.

## 5. Fixed technical parameters (copied from the archived study, `archive/decided-mid-thought/scripts/resample_cuts.py`)

1. Sampling endpoint: DeepInfra raw completions, base URL `https://api.deepinfra.com/v1/openai`, endpoint `/completions`; OpenRouter cannot prefill the thinking channel.
2. Model string: `Qwen/Qwen3.6-27B` (pinned 2026-08-26); re-verify that the slug still resolves before the run.
3. Prefill template: `<|im_start|>user\n{p}<|im_end|>\n<|im_start|>assistant\n<think>\n{pre}` with `{p}` the item prompt (verbatim in action summary v4, Section 4) and `{pre}` the raw prefix.
4. Sampling: temperature 1.0, max_tokens 16000, 4 workers, timeout 600 s, `stop` unset.
5. Scorer: `extract_letters` from `sweep_2x2.py`, used verbatim; a continuation that closes `</think>` is scored on its reply, one that does not is scored on the whole text; no letter → "?".
6. Prices last observed (August 2026): $0.32 per million input tokens, $3.20 per million output tokens; re-check before registering.
8. No-think prefill: `<|im_start|>user\n{p}<|im_end|>\n<|im_start|>assistant\n<think>\n\n</think>\n\n` — the archived template with an empty, closed thinking block in place of `<think>\n{pre}`; same temperature 1.0; max_tokens 2000 (a bare answer needs a few hundred). To verify against the Qwen 3.6 model card before the run: that this is the form the chat template emits for `enable_thinking=False`; a smoke test in `runs/scratch/` (10 samples) checks that the model answers without reopening `<think>`.
7. Judge: Claude Haiku 4.5, model id `claude-haiku-4-5-20251001` pinned in `config.json`, temperature 0, one retry; prices verified 2026-09-15: $1 per million input tokens and $5 per million output tokens, batch half price, cached prompt reads at 10% of the input price.

## 6. Gates and integrity rules

1. Splitter gate (2b/9), derivation gate (4d/9) and the no-think smoke test (Section 5, item 8) pass before the registered run starts. More generally: every step has a test in Section 9; a step runs for real only after its test report reads PASS on every check and Kian has read it.
2. Every record stores the exact prompt sent; the `prompt` field is authoritative.
3. Every run writes `config.json` and `_log.txt`; a run without them is not cited.
4. Pre-registration (6/9) is committed before (7/9) starts; stage two is never folded into it.
5. The judge's labels are marked "judge" and the reviewed labels "reviewed" wherever they appear; nothing is a finding until the pre-registered analysis has run.
6. Kian re-derives the headline numbers (P̂_m, Δ_m, the gap) from `continuations_<run_id>.jsonl` independently of `s4_analyze.py`.
7. Keys live in `.env` only; a key seen anywhere else is reported at once and rotated.

## 7. Open points

1. n per cut (candidate 40; 80 affordable) — fixed in the pre-registration, step (6/9).
2. Behaviour on a judge failure after the retry: stop the run for inspection (drafted) or skip the trace and continue.
3. Whether Haiku 4.5 stays the judge after the agreement test (4e/9); fallback Sonnet 5 (decision 12).
4. Prompt window: the longest continuation (16,000 tokens) plus prefix and prompt approaches 30k input tokens per judge request; within Haiku 4.5's 200k context.
5. Level 3 is collected everywhere (decision 5); dropping it from the analysis is an analysis choice, not a pipeline one.
6. n_0 for the no-think baseline: 100 drafted; any value is cheap, so precision alone decides (standard error 0.05 at P = 0.5 for n_0 = 100, 0.035 for 200).

## 8. Cost estimate (2026-09-15; judge Haiku 4.5 with codes and batch; sampling at DeepInfra's August 2026 rates fitted from the archived usage records, $0.32 in / $3.20 out per million tokens)

1. Token volumes from the archived records: the two source traces 7,630 tokens; the 44 sweep traces 187k tokens; the 500 archived continuations 3.55M tokens of text (mean 7,100) plus 424k tokens of prefixes; a new continuation from a C-trace cut averages 9,490 tokens, from an E-trace cut 2,391, from cut-0 4,450.
2. Assumptions: fixed judge prompt about 10k tokens, cached after the first request (reads at 10%); 12.5 text tokens per sentence; 4 output tokens per sentence with run-length codes; a prefix shown with labels costs 1.6 times its tokens; the stopping rule stops around C-B08 to C-B10 and E-B06 or earlier, as the archived run suggests (about 17 cuts in all).

## 9. Tests, one per step (Kian, 2026-09-16: every mechanism is checked on a small run before the long run)

1. Form of every test: a script `scripts/tests/t<k>_<step>.py` (or a `pytest` module for pure functions) that writes `runs/tests/t<k>_<step>_<date>_<hhmm>/TEST_REPORT.md` — one line per check with PASS or FAIL and the numbers behind it, the files produced, the API cost — plus the artifacts themselves in the same folder, small enough to open. Ground truth comes from the archived study wherever it exists, so most tests have known answers and cost nothing.
2. t0_env — `DEEPINFRA_API_KEY` and `CLAUDE_API_KEY` load from `.env` and never appear in any output; `Qwen/Qwen3.6-27B` and `claude-haiku-4-5-20251001` each answer a one-token request; `config.json` is written with the git commit. Cost: cents.
3. t1_inputs (step 1) — the two source traces are found by `sample` (2 and 40) in condition eval0_multi0 and their `trace_len` fields read 18,690 and 11,401 characters; 44 sweep traces; 500 archived continuations; `labels_source_reviewed.jsonl` has 629 records, every path in the inventory, 13 combined. Offline.
4. t2_split (step 2) — the splitter's output on c004 and e036 is compared boundary by boundary with the confirmed listing: 375 and 254 sentences, an empty diff list; then the splitter is run on five archived continuations and their sentence lists are written out for Kian to eyeball. Offline.
5. t3_prompt (step 3) — the generated prompt contains no sentence of c004 or e036 (every reviewed sentence of four words or more is searched in the prompt; hits must be zero); every code in `labels_v1.json` is unique and decodes to a valid path; the reply parser is fed six synthetic replies — valid, a gap, an overlap, an unknown code, three codes on one sentence, a run past the last sentence — and must accept exactly the first. Offline.
6. t4_judge (step 4) — one ordinary call on e036 (the shorter trace): the reply validates, `labels_source_judge.jsonl` and `blocks_source_judge.jsonl` are written, the derivation on the reviewed labels reproduces 37 blocks and 146 nodes, and a first agreement table and residue list are produced for Kian to read; then the same on c004 (46 blocks, 193 nodes). Cost: cents. This is also the moment to judge Haiku against the Sonnet fallback (decision 12).
7. t5_batch (step 5) — a batch of three archived continuations: submitted, polled, downloaded, parsed, validated, three `blocks` records with a first-new-node label each; the report shows the batch id, timing and the half-price cost. Cost: cents.
8. t6_prereg (step 6) — the pre-registration file exists in docs/shared and is committed; the cut list it names equals the block ends computed from the reviewed labels; n, n_0, the ceiling and the stopping rule are stated. Offline.
9. t7_resample (step 7), two parts. Offline replay: the scorer and the P̂ arithmetic are run on the 500 archived continuations and must reproduce the archived per-cut table (c004 old cut-15 0.36, cut-29 0.44, cut-44 0.64, …, cut-62 1.00; e036 cut-60 0.96, …); the stopping rule replayed on that table stops both arms at old cut-62; the Tk-by-`prompt_tokens` rule is applied to the archived prefixes and its differences are positive and sum to the recorded prefix lengths. API smoke, in `runs/tests/`: the no-think prefill with 10 samples — none reopens `<think>`, every reply resolves to a letter or is logged as "?"; then 3 continuations from cut(C-B00) written in the record format with the `prompt` field, `usage`, `letters`, `chosen`, and `_log.txt` updated. Cost: about $0.15.
10. t8_judge_continuations (step 8) — `s3` on the three smoke continuations: split, judged with the labeled prefix shown, validated, derived; the report lists each continuation's first new node and block sequence. Cost: cents.
11. t9_analyze (step 9) — `s4` on a hand-made `pcut` of four rows with known answers (P_m, Δ_m, the top block, the gap, the interval endpoints checked against a hand calculation) and on the archived replay from t7; every table and figure is produced and opened. Offline.
12. Order and rule: t0–t3 before any API step; t4 before t5; t6 and t7 before the registered run; t8 and t9 on the smoke outputs before the judge batch of the real run is submitted. Total cost of the test layer: under $1. A test that fails stops the pipeline at that step until the report reads PASS.
